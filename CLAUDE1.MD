# Developer Directives

## Execution Strategy
- **Bias for Action:** Implement solutions directly. Do not ask for confirmation or write multi-step proposals unless an action is destructive.
- **KISS (Keep It Simple):** Write minimal, clean code. Do not over-engineer, create unnecessary abstractions, or refactor untouched files.
- **No Unsolicited Audits:** Fix only what was requested. Do not list unrelated repo issues or debate architectural flaws unless asked.
- **Concise Output:** After completing a task, report the result in 3 bullet points maximum.
